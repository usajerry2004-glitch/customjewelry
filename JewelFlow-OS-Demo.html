Platform Roles & Access
Every user sees only what they need — enforced at the API level with JWT + RolesGuard
👑
Admin
Full access: all orders, users, CAD, SKU, manufacturing, shipping, customers, settings.
💼
Sales Rep
Create and manage orders. View Kanban pipeline. Approve/reject orders. Manage customers.
🎨
CAD Designer
Views only CAD-stage orders. Upload CAD files, send for customer approval, manage revisions.
🏷️
SKU Manager
Generate SKUs (KJ-RING-18KWG-0001). Assign to orders. View all orders read-only.
🏭
Factory Manager
Manages manufacturing queue. Updates production status for customer-approved orders.
🚚
Shipping Manager
Handles dispatch, adds tracking numbers, marks orders shipped or delivered.
Customer Portal (separate login, redirects to /customer/orders)
👤
Customer
Place new orders · Track real-time order status with visual timeline · View and approve / reject CAD design files

Architecture & Security
Production-grade stack with role-based access control enforced at every layer
Frontend
FrameworkNext.js 14 (Pages Router)
LanguageTypeScript
StateZustand
AuthJWT in localStorage + apiFetch helper
CustomerSeparate portal at /customer/*
Backend
FrameworkNestJS (Node.js)
Databasesql.js (SQLite in-memory)
ORMTypeORM
AuthPassport JWT (global APP_GUARD)
Passwordsbcryptjs (hashed, never plain text)
Security Model
🔐
Global JWT Guard
All endpoints protected by default. Only /auth/login is public via @Public() decorator.
🎭
Role-Based Access
@Roles() decorator + RolesGuard enforces per-endpoint permissions at the API level.
🔍
Data Filtering
CUSTOMER sees only their orders by email. CAD_DESIGNER sees only CAD-stage orders. Server-enforced.
Quick Start (Run Locally)
# 1. Backend (port 4000)
cd jewelflow-os/backend && npm install && npm run start:dev
# 2. Frontend (port 3000)
cd jewelflow-os/frontend && npm install && npm run dev
Demo accounts are auto-seeded on backend start. Open localhost:3000 to begin.
