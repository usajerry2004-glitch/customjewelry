Platform Overview — 5 User Roles

Who Uses JewelFlow OS

Each role sees a tailored interface. No role can access data or actions outside their permissions.

👑
Admin
Full access to all pages, orders, users, settings, SKUs, and workflows. Sees all data.
admin@kirajewels.one
💼
Sales Rep
Views all orders, creates orders, approves / changes order status through the pipeline.
sales@kirajewels.one
🎨
CAD Designer
Sees only CAD-stage orders. Uploads design files, sends them to customers for approval.
cad@kirajewels.one
🏷️
SKU Manager
Manages SKU catalog. Generates SKU numbers from order specs. Auto-format: KJ-RING-18KWG-0001.
sku@kirajewels.one
👤
Customer
Separate portal. Can place orders, track status, view and approve CAD design files.
customer@example.com

Security & Architecture

Every request authenticated. Every role enforced server-side.

🔐
JWT Authentication
• All API endpoints protected by default
• Bearer token required on every request
• Tokens expire after 7 days
• bcrypt password hashing (10 rounds)
• Public routes explicitly opt-out with @Public()
🛡️
Role-Based Access Control
• @Roles() decorator on each endpoint
• RolesGuard checks JWT payload server-side
• Customer data isolated by email filter
• CAD Designer sees only CAD-stage orders
• Status changes restricted to Sales/Admin
⚡
Tech Stack
• Frontend: Next.js 14, TypeScript, Zustand
• Backend: NestJS, TypeORM, Passport.js
• Auth: JWT, bcryptjs
• Storage: SQLite (production: PostgreSQL)
• Files: Multer disk storage
🔄
Order Workflow
• 15-stage pipeline from Confirmation → Delivered
• CAD upload auto-advances order status
• Customer approval triggers pipeline move
• SKU auto-generated from order specs
• Real-time notification bell (30s poll)
